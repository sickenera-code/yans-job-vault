# CLAUDE.md — Yan's job vault

本目录是 Obsidian 仓库，也是 Claudian / Claude Code 的项目目录。以 `00-我的简历.md` 为候选人事实来源，以 `00-我的简历-深挖分析.md` 和 `简历分解/` 支持经历深挖，以 `已投递岗位/` 积累岗位资料。年份、行业和候选人背景从当前简历及用户说明判断，不沿用任何示例人物。

## 日常任务

- 简历 / 面试准备：先读简历和对应经历概览，再读岗位 JD；检索相关准备语料即可，不必每次全文遍历整个仓库。第一人称答案使用候选人自然表达，不出现“我看了你的简历”“我的语料库里写过”。未知经历和指标明确标记待补，不能写成事实。
- 新增投递：记录用户已投递的岗位。创建 `已投递岗位/NN-公司 岗位.md` 和同 stem 文件夹，文件夹内放 `00-资料索引.md` 并回链岗位页；回写数据的 `notePath`、`folderPath`。序号取所有现有笔记和目录的最大编号 + 1。同名路径已存在时检查关联 id，不覆盖原稿。可调用已安装 yans-job-vault 的 `scripts/vault.py add-job`。
- 岗位定向资料：先定位岗位职责/任职要求，把资料保存到该岗位同名文件夹，顶部加 `[!info] 资料定位` 和岗位回链；长文使用 `[[#章节]]` 目录。岗位页 `## 📚 关联准备资料` 表末尾追加一行，列为“资料 / 重点映射 JD 维度 / 关键覆盖点 / 资料价值”。**资料价值留空，由用户填写**；已有行保留。同步更新资料索引。
- 简历拆分：按候选人实际教育、每段实习/工作/项目/实践和关键能力建立经历目录，概览保留原句、原文定位、报告链接和待补证据。新增语料归属到相应经历目录，避免大段重复存放。
- 当前岗位要求、公考公告、公司数据及专业法规需查询官方来源并注明日期；仓库已有笔记只作资料线索，不能把历史内容当成当前事实。

## 数据与页面

`投递进度.md`、`秋招关注.md` 是交互页面；`Resource/投递记录数据.md`、`Resource/秋招关注数据.md` 的带标记 JSON 数组是唯一持久化数据。保留标记、JSON 格式、未知字段与区块外正文。不能把新数据放进页面代码或 localStorage。发现 JSON 损坏时保留原件修复，禁止用空数组覆盖。

Agent 写数据前停止操作对应页面，备份数据、读取最新文件，再修改目标字段；完成后重开页面刷新。当前实现没有跨窗口/跨进程事务锁。阶段、Offer、链接改动需保持岗位笔记相关字段一致，其他准备正文不重写。

删除投递条目默认保留笔记和准备目录。重命名岗位时同时维护笔记、目录、`notePath`、`folderPath` 和双向链接。页面新增目录失败时保留投递记录，重开页面会补齐；也可用 skill 的 `sync-jobs` 修复。

保留现有页面的排版和交互结构。`公考时间.md` 为原样保存的 2026.1—2027.6 参考时间轴，未请求时不自动改年份、政策或日期。

## Markdown 与媒体

使用 Obsidian 双链、callout、必要的 `==高亮==` 和清晰标题。已安装 `obsidian-markdown` 时可调用；未安装则按本规则直接执行，不依赖不存在的 skill。

- 图片统一存 `Resource/Images/<主题>-<序号>-<内容描述>.<ext>`，例如 `面试准备-01-项目流程.png`。名字要体现图中内容，不能只有 UUID/hash/时间戳。不要为换名字重复生成图片。
- 用 `![[Resource/Images/实际图片名.png]]` 就近嵌入对应段落。岗位和经历目录存 Markdown，媒体不另建零散 assets 目录。
- 简历原件存 `Resource/Resumes/`，其他附件存 `Resource/Attachments/`，同样采用语义化文件名。
- 用户要求生成或整理配图时使用当前环境可用的图像能力。已有媒体按工具允许方式保存；工具限制下载时保留可用引用并说明，不能假装已保存本地。
