## 打开与使用

1. 在 Obsidian 中选择“打开文件夹作为仓库”，选择本文件夹。
2. 安装并启用 **Dataview**，在其设置中开启 **Enable JavaScript Queries**，用阅读视图打开上述页面。仅复制 Markdown 不会自动安装插件。页面使用 Dataview JavaScript 接口，见 [Dataview 官方说明](https://blacksmithgu.github.io/obsidian-dataview/api/intro/)。
3. 在“投递进度”录入企业、岗位和投递日期。系统会保存记录，并生成岗位笔记及同名资料文件夹，里面的“00-资料索引”会链接回岗位。
4. 在“秋招关注”记录关注企业、预计开放月份和备注；真正投递后再在“投递进度”登记。
5. 在 Obsidian 中安装并启用 Claudian，配置当前使用的 Agent CLI 和账户。通过插件引用自己的简历、岗位页或资料让 Agent 处理。[Claudian 官方项目](https://github.com/YishenTu/claudian) 提供安装与运行要求；本仓库不包含个人账户设置。

交互页面的界面结构沿用提供者模板。自定义字体可能需要联网加载，无法加载时使用系统字体。核心记录在本地 Markdown，不依赖浏览器缓存。

## 简历与语料

初始化 skill 会根据用户提供的真实简历生成简历正文、深挖报告和经历目录。仅运行初始化脚本时，这三个内容产物尚未生成，需要 Agent 继续读取简历并完成分析。

每个“简历分解”子文件夹服务一段真实经历或关键能力主题；针对某个岗位的调研和面试准备放入“已投递岗位”下对应的同名文件夹。图片统一放 `Resource/Images/`，原始简历放 `Resource/Resumes/`，其他附件放 `Resource/Attachments/`，采用能看懂的名字。

整理岗位资料时，Agent 会追加岗位页关联表格，并将“资料价值”留空，方便你写下自己准备在面试中怎样引用。

## 保存与修复

数据保存在 [[Resource/投递记录数据]] 与 [[Resource/秋招关注数据]]；随仓库一同备份或同步。不要改 JSON 标记。两个窗口或 Agent 不要同时修改同一张表，外部修改后重新打开交互页再操作。

删除列表条目保留该岗位的笔记和准备材料。目录创建失败时，修复路径占用或写权限后重开“投递进度”，页面会补齐。导入会替换列表，请先用导出按钮备份；已有资料笔记不随导入清空。

`公考时间.md` 是原样保存的 **2026.1—2027.6** 时间轴，适用年份和报名安排需要查看官方公告；初始化不会自动把这份历史参考表改成当前公告。

Claude/Claudian 规则入口为 `CLAUDE.md`；Codex 入口为 `AGENTS.md`。如需重新调用部署 skill，读取完整的 `yans-job-vault/SKILL.md`，不要把模板空数据覆盖进正在使用的仓库。

## 从夯到拉评级

打开 [[已投递岗位/00-从夯到拉]]，将岗位卡片从候补池拖入“夯 / 顶级 / 人上人 / NPC / 拉完了”五档；拖回候补池取消评级，双击打开对应岗位笔记。“清除评级”只清除分类，不删除岗位和准备资料。

评级保存在 [[Resource/岗位评级数据]]，随仓库备份和同步。初始没有预设评级。评级板读取岗位笔记，新增投递生成笔记后会进入候补池；从投递列表删除但保留的岗位笔记仍会显示。重命名岗位笔记需要同步更新评级数据中的路径。其他窗口或设备修改评级后，重开页面读取最新数据。
