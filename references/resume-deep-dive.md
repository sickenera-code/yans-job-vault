# 内置简历深挖流程

本流程整合随本地环境提供的 `resume-deep-dive`：全景诊断 → 逐句五维深挖 → 最短学习路线。来源检查见 [来源说明](provenance.md)。输出前读取 [输出模板](resume-output-templates.md)。

## 求职定向

从对话和简历确定行业、岗位、公司类型、求职阶段。已知信息直接复用，不重复提问。未知项标为待确认；可将简历显著方向作为临时假设，写明依据。方向可能影响结论时，把定制意见与通用意见区分。

首次部署要求交付完整文件，默认全部深挖，不套用原技能“每处理几句就等待用户选下一句”的交互限制。只是维护或深挖片段时按用户范围处理。

## C：全景诊断

按模板评价模块完整性、模块顺序、篇幅控制、视觉可读性，每项 1–5 分并给依据。未看到原始版式时不能给视觉评分或声称总页数；标为未评估，综合分只对已评估项求和。ATS 部分检查提取顺序、表格/多栏/图片风险、关键词和动词；不要宣称 Markdown、emoji 或表格天然适合所有 ATS。

列出亮点、硬伤、行业/岗位能力对照及修复优先级。用具体 JD 或注明属于一般岗位经验，不伪装成已经访问某公司内部录用标准。建议添加技能前先核实用户确实掌握。

## A：逐句五维深挖

为所有实质性经历陈述编号（教育基本字段可以合并；每条实习/工作/项目行动和成果均须覆盖），建立原文覆盖清单。每条包含：

1. 字面信息：做了什么、对象/工具/成果、信息密度、关键词。
2. 面试官视角：好信号、危险信号、可能验证的疑问。不因“协助”一词直接判定无价值，先厘清实际职责。
3. 考点与能力：能力权重、知识链路，挂到目标岗位。
4. 追问链：每个核心能力三层 Q1 破冰 → Q2 细节 → Q3 边界，分别提供回答思路；至少一组完整 S/T/A/R 框架。
5. 优化与盲区：原句问题、保真改写、改动理由、至少一个待验证知识点/证据缺口、优先级和对应经历文件夹链接。

**保真规则**：区分“简历已陈述”“合理推断”“需要用户补充”。不能把团队成果改成个人独立成果，不能把理论知识改成实操经历。缺少量化成果时保留定性描述，或用明确的 `〔待补：统计口径/数值〕`。推荐回答中的未知决策过程、工具细节和 STAR 结果同样标记，不替用户编造可背的经历。不要声称 Agent 本人有“100 场面试”从业资历。

## B：最短学习路线

汇总高优先级盲区。每个需要规划的关键技能提供 3 道自评题，区分概念、动手实践、系统表达四档起点；用户未作答时标为“待自评”，在报告里留下题目及起点映射即可。无需等待自评而中断仓库交付，也不能伪造自评结果。

用户作答后，按 20% 概念框架 / 50% 核心方法 / 30% 面试表达安排具体任务、产出、自检，附 1–2 天极速版和暂不学习范围。默认不超过两周。不能声称某内容绝不被问到；排除项解释为当前岗位和时间预算下优先级较低。

## 文件交付

写到 `00-我的简历-深挖分析.md`：求职画像与假设、原件/原文链接、全景诊断、覆盖清单、五维卡片、盲区与自评/学习路线、可执行补充事项。不要只把长内容留在聊天窗口。

清单按编号将每条原文对应至报告章节和 `简历分解/NN-经历/00-经历概览.md`。有英文面试需求时补充英文表达；事实边界与中文保持一致。日后对某一条更新时保留用户已经补充的真实答案。

本地源文件没有作者标注，不在生成报告里虚构署名。需要方法来源说明时可写“分析方法：全景诊断、逐句五维深挖与学习路线”。以后有确切作者信息时，在报告方法说明中标注真实作者和出处。
